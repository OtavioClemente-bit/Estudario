# IA integrada beta: acceptance runbook

Run from the `codex/ia-api` worktree. Keep provider and Supabase service credentials in the deployed server environment; Android needs only the approved project URL and publishable key. Use disposable beta, non-beta, and second-account identities for live acceptance.

1. Reset and verify the local schema: `npx supabase db reset`, then `npx supabase test db`. The pgTAP suite exercises migrations, atomic quota and cancellation, private syllabus RPCs, and account A/B RLS and Storage paths.
2. Run all Edge Function tests with type checking: `npx --yes deno test --no-config --node-modules-dir=none --allow-all supabase/tests/functions supabase/functions`. Include provider failure, malformed output, adversarial PDF, limits, binding, safe errors, idempotency, and reconciliation cases.
   The private-library PUT body is independently capped by `MAX_PRIVATE_SYLLABUS_BYTES` (default 50 MiB, matching the existing `MAX_PDF_BYTES` fallback); an oversized body returns `413 PRIVATE_SYLLABUS_TOO_LARGE` before JSON parsing or storage. Set a lower positive byte value in the server environment if the deployment needs one.
   New syllabus job creation has a separate fixed 10-minute rate counter per authenticated user, default 3 accepted attempts. The server-side `public.ai_syllabus_rate_limit_config.max_attempts` row controls that number. An idempotent retry with the same key and fingerprint does not consume another attempt. The `AI_RATE_LIMIT_EXCEEDED` response is HTTP 429 with `error.retryAfterSeconds` and `Retry-After`; processing, reads, recovery, and cancellation do not consume this counter. The existing non-renewing syllabus quota is separate and defaults to one reservation, so exercise the rate cap in a disposable environment with that quota raised.
3. With the configured Android SDK/JDK and an approved emulator or device, run `.\gradlew.bat testDebugUnitTest`, `.\gradlew.bat connectedDebugAndroidTest`, and `.\gradlew.bat :app:assembleDebug`. Review the XML per device if the connected task fails; distinguish test assertions from `INSTALL_FAILED_USER_RESTRICTED`.
4. Before a staging release, deploy the reviewed migrations, RLS and Storage policies, Edge Functions, durable worker schedule, feature flags, quotas, and server secrets. Exercise one readable PDF and one adversarial/unreadable or over-limit PDF with the disposable accounts. Confirm the provider is never called before the source path and server hash are bound, and that errors contain no raw document or secret.
5. On Android, confirm a double tap reserves one job, a timeout resumes by the same job ID, local apply creates one pending outbox mutation, a failed sync stays pending/failed without claiming account save, and reinstall/download restores the complete identity-bearing tree. Check local deletion leaves the remote copy until explicit account deletion.
6. Run `git diff --check` and the repository secret scan from the implementation plan. Inspect matches as references versus literal credentials. Record command outcomes and any missing external configuration in `.superpowers/sdd/2026-09-23-ia-integrada-beta-edital/task-16-report.md`.

Do not promote a build while required acceptance suites are red or live project/account/provider checks have not been performed.
