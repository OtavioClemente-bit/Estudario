# Modo Foco Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put Focus in the center of the bottom navigation, preserve each timed session in its own history, and keep focus time separate from topic and plan completion rewards.

**Architecture:** Keep the currently active session in DataStore and save each finished session in a new Room table with a stable ID. Use the new history for focus XP and study-time reporting, while leaving topic completion and plan execution as explicit actions. Keep the existing notification and four-hour safety worker as alternate ways to resume or end the same session.

**Tech Stack:** Kotlin, Jetpack Compose Material 3, Navigation Compose 2.9.3, Room 2.7.2, DataStore Preferences 1.1.7, WorkManager 2.11.2, JUnit 4.13.2, AndroidX Room migration and Compose tests.

**Spec:** `docs/superpowers/specs/2026-09-22-modo-foco-e-fila-design.md`

## Global Constraints

- The current Room database is version 13; add migration 13→14.
- Free focus earns 1 XP per 10 complete minutes summed per local day, capped at 10 XP per day.
- Focus started from a topic or plan task earns no focus XP; its topic or task must be completed explicitly.
- Closing focus must not complete a topic, plan task, or queue item.
- An active session survives app closure and resumes from its original start time, subject to the current four-hour safety closure.
- Keep the existing Android notification and Do Not Disturb restoration behavior.
- Existing backup versions remain restorable; new backups include focus history.
- Preserve pre-existing workspace edits. Before each commit, inspect the diff and stage only the hunks belonging to that task; do not stage an already-dirty file wholesale.

## Review Focus

- Version 13 focus rows must move to the new history without changing their recorded duration; pin this in `AppDatabaseMigrationTest.migrateThirteenToFourteenSeparatesLegacyFocusRows`.
- A running session created before the update has no stable ID or selected-subject list; pin deterministic recovery in `FocusSessionPrefsTest.legacyActiveSessionGetsStableIdentity`.
- Ending through the screen and notification twice must not duplicate history; pin this in `FocusSessionRepositoryTest.recordOnceIgnoresDuplicateSessionIds`.
- A database insert failure must leave the active session available to retry; pin save-before-clear ordering in `FocusSessionStopCoordinatorTest.saveFailureKeepsSessionActive`.
- Free focus must be the only focus source of XP; pin this in `ProgressEngineTest.focusXpIsFreeOnlyAndCappedPerDay` and `ProgressEngineTest.linkedFocusEarnsNoFocusXp`. Explicit topic completion remains one-time; pin this in `StudyRepositoryCompletionTest.focusSessionDoesNotCreateTopicCompletionReward`.

## File Map

- `Entities.kt`, `Converters.kt`, `AppDao.kt`, and `AppDatabase.kt` define and persist `FocusSessionEntity`; the 13→14 migration transfers legacy focus records.
- `FocusSessionRepository.kt` reads and inserts focus history exactly once.
- `AppPreferences.kt` stores the active session ID, subject IDs, and origin so reopening the app restores the same timer.
- `FocusSession.kt` coordinates session start/stop, the notification, Do Not Disturb, and safety closure.
- `AppViewModel.kt`, `ProgressEngine.kt`, `StreakEngine.kt`, and `StudyPerformanceInputMapper.kt` keep focus activity, XP, session counts, and minutes distinct from topic completion.
- `BackupService.kt` includes the new history in the next backup format while accepting older files.
- `FocusScreen.kt`, `EstudarioApp.kt`, and a small focus navigation icon component provide subject selection, active timer, history, and the center navigation destination.
- `PlanScreen.kt` stops opening completion automatically when a focus timer ends; plan completion stays explicit.
